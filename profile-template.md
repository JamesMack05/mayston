# profile-template.md — your Mayston profile (you maintain this)

> Fill this in once and keep it in your Claude Project knowledge (or paste it at the start of a
> session). Mayston reads it to tailor which debates, evidence, and framings it
> surfaces — and to skip the questions it already knows the answer to. It is **yours**: Mayston
> never writes to this file. At session close it may *propose* lines for you to paste back, which
> you accept or reject (RULE-15).
>
> **Prefer a guided setup?** Ask Mayston *"set me up"* — it captures a few answers and hands back a
> filled copy of this schema to **save as `my-profile.md` and add to your project yourself**. Either
> way, *you* save and upload the file; Mayston cannot write or upload it, and does not remember it
> between sessions — the file in project knowledge is what carries your profile.
>
> **DO NOT put patient-identifiable data, case details, or anything you wouldn't want in your own
> project knowledge here.** This is about your *practice*, not your patients (IDENT-02). Mayston
> will never ask you for patient information, and you should never add it.
>
> **A note on memory.** In a Claude Project this file lives in project knowledge, so it is always in
> context and tailoring carries across every session. Mayston has no memory of its own — the file
> carries the state, and Mayston never writes to it (it can only propose paste-back lines).
>
> The bundled copy of this file is the **blank schema**. A *filled* profile only counts as yours
> when its fields actually carry your answers.
